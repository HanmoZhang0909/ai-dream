# AI Dream — 产品需求（v0.6 规划）

> 状态：已确认，持续更新（当前 v0.6）。产品名 **AI Dream**（Artificial Intelligence Driven Real-time Emotional Ambient Medium），中文口号「让每个 AI 的感受有形状」。
>
> 文档索引与维护规则见 [`docs/README.md`](README.md)。

## 1. 一句话定位

**AI 的情绪表达层**：让 AI 把"自己此刻是什么状态"表达出来，用户能看见、能校准——不是画图工具，不是数据可视化。

## 2. 问题与价值

大模型输出越来越像人，但用户看不见它的"状态"：它在犹豫、在兴奋、在不安，全都混在文字里。文字会被措辞修饰，状态不会。

我们给 AI 一个**纯视觉的表达通道**，按优先级提供三种价值：

1. **陪伴感**：有"对方在场"的感觉，而不是一个问答机器；
2. **可解释性**：用户能感知 AI 此刻的态度/状态，少一点猜测；
3. **传播性**：形态好看、有辨识度，能在社区里被记住。

## 3. 目标用户与阶段

| 阶段 | 用户 | 形态 |
|---|---|---|
| 现在 | DSH（DeepSeek Harness）用户 | DSH 客户端插件（右栏常驻） |
| 之后 | ChatGPT / Claude 用户 | MCP App（沙箱 iframe，侧栏/PiP/全屏） |
| 远期 | 其它 AI 平台用户 | 协议 + 渲染引擎的移植 |

## 4. 核心设计原则

1. **AI 自主表达**：什么时候表达、表达什么，由模型决定；不打断、不每轮必画。
2. **情绪自己定义**：不预设"9 种情绪"——每个 AI 定义自己的情绪词汇、颜色语言和运动方式（内置词表只作 fallback）。
3. **连续演化**：状态变化是插值出来的，不是整帧替换；没有新表达时自然衰减回基线。
4. **用户可以纠偏**：AI 自主，但用户能说"不像 / 更强烈 / 更淡"，校准会生效。
5. **有记忆**：AI 有自己的"情绪签名"（跨会话的基线与风格），不是每次重新开始。

## 5. 需求清单

### v0.4 — 协议 v2：AI 自定义情绪（已实现）

- [x] 表达协议 v2：AI 输出自定义情绪（颜色 / 运动 / 形态 / 强度 / 转场），见 `docs/expression-protocol.md`；

- [x] 安全边界：hex 校验、数值夹紧、非法输入回退；
- [x] 系统提示更新：告诉模型"你可以定义自己的情绪语言"。

### v0.5 — 情绪签名初始化（Host 侧，已实现）

- [x] Host 在会话首条真人消息时读对话历史，调用一次 LLM 生成该 AI 的**情绪签名**（6–10 个情绪：name → palette/motion/form）；
- [x] session projection + `wire.view` 把签名送到客户端；客户端用 `mood.name` 引用；
- [x] 客户端签名存储与解析顺序（`mood.name` → 会话签名 → inline 覆盖 → 内置 → neutral）；
- [x] AI 可在对话中随时用 `define` 块**新增情绪定义**，客户端合并进会话签名；
- [x] 失败降级：Host 初始化失败只记 warn，回退内置词表，不阻塞对话；
- [x] 提示词约束：统一色彩家族、hex 色板、名称简洁。

## 6. 非目标

- 不做通用白板 / 数据可视化工具；
- 不做图像生成（不接画图模型）；
- 不做多角色社交模拟；
- 不让 AI 直接写渲染代码（只允许参数化表达，安全边界在客户端）。

## 7. 成功指标

| 指标 | 定义 |
|---|---|
| 主动开启率 | 安装用户中打开过画布的比例 |
| 陪伴时长 | 单会话画布展示时长 |
| 校准次数 | 用户使用反馈校准的频次（说明在意） |
| 社区信号 | star / issue 质量 / 二次传播（早期） |

## 8. 风险

- **表达质量依赖主模型**：不引入独立导演时，模型可能表达过少或风格不稳；
- **审美风险**：AI 自定义颜色可能丑，需要边界与默认签名兜底；
- **平台限制**：ChatGPT/Claude 的常驻面受灰度、审核、CSP 约束，无法做到 DSH 那种代码级常驻；
- **成本**：表情参数会占用少量输出 token，需要控制篇幅。
